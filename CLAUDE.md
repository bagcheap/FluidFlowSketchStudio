# CLAUDE.md — FlowSketch Studio

Browser-based editor for hand-drawn flow diagrams that gently animate: shapes float, wobble or "boil", and arrows show flow with a travelling highlight, draw-on, marching dashes or pulse. It saves editable `.flowsketch` files and exports animated GIF, video, PNG/JPEG, SVG and a standalone HTML player. Everything runs locally in the browser; there is no backend and no account.

Owner: Angus (macOS, technically capable). The repo is `github.com/bagcheap/FluidFlowSketchStudio`. FlowSketch is a **personal learning project, not published or distributed**; licensing and third-party terms are summarised in `THIRD_PARTY_NOTICES.md` (keep it current when adding dependencies or icon sets).

## Commands

```bash
npm install
npm run dev          # Vite dev server, http://localhost:5173
npm run build        # rebuilds the HTML-player bundle, type-checks (tsc --noEmit), then vite build → dist/
npm run preview      # serve dist/ on :4173
npm test             # Vitest unit tests (tests/*.test.ts), must stay green
npm run typecheck
npm run build:player # rebuild src/player/player.bundle.js (needed only after engine changes)
npm run app:dev      # desktop app window (Tauri) on top of the dev server
npm run app:build    # desktop app: src-tauri/target/release/bundle/macos/FlowSketch.app (+ .dmg); needs Rust
```

End-to-end checks are in Python with Playwright and Pillow, and drive the real UI:
`npm run build && npx vite preview --port 4173 &` then `python3 e2e/run_e2e.py http://localhost:4173/ <out_dir>`.
`python3 e2e/make_samples.py` regenerates `samples/*.flowsketch` and `samples/*.gif` through the UI.

Before saying a change is done: `npm run typecheck`, `npm test`, and for UI or interaction changes, run the e2e suite or at least check the behaviour in the browser.

## Stack

React 18 + TypeScript (strict) + Vite, Zustand for state, Rough.js for sketch geometry, gifenc in a Web Worker for GIFs, idb-keyval for IndexedDB, Lucide icons, Kalam (hand) and Inter fonts via @fontsource.
UI styling is **plain CSS with design tokens** in `src/styles.css`. There is no Tailwind. Menus and dialogs are **hand-written accessible components**, not Radix. Keep it that way unless asked.

### Rules that must not be broken

1. **Animation never mutates the document.** `renderDocumentAtTime(doc, t)` in `engine/render.ts` is pure and deterministic. Live playback, every export and the HTML player call it, so the preview and exports match. Never write animated positions back into saved coordinates.
2. **Hit-testing, selection handles and connector editing use STATIC geometry**, never animated geometry. They live in the SVG overlay in `Canvas.tsx` and in `hitTest.ts`.
3. **Seamless loops:** temporal frequencies are snapped to whole cycles per loop (`snapFreq` in `noise.ts`). Squiggle intensity 0 must be *exactly* still. Motion must be continuous; there are unit tests for this.
4. **Static roughness (Style.roughness) and animated squiggle (anim.intensity) are independent settings.**
5. **Connectors are real relationships** (`Endpoint.elementId` + optional `anchor`), resolved against the *animated* target transform so arrows stay attached while shapes move.
6. **Rough.js geometry is generated once and cached** (`engine/rough.ts`) per geometry, style and seed. Each frame only transforms or warps it. Don't regenerate paths per frame.
7. **Imported files are untrusted.** Everything goes through `parseDocument` in `model/schema.ts`: coerce every field, raster-only images (SVG only ever enters as an **icon**: `svgToIcon` keeps plain geometry and paint, and `sanitizeIconAsset` re-validates icon data on every load), detach dangling references, no executable content. Bump `SCHEMA_VERSION` and add a `migrate()` case for any format change.
8. **Undo/redo:** use `commit(fn, coalesceKey?)` for discrete edits (rapid slider changes coalesce on the key). Use `begin()` / `live()` / `end()` (or `cancel()`) for drags, so one gesture is one history entry.
9. **Saved preferences are untrusted too:** `sanitizePrefs` (uiStore) type-checks every setting and runs remembered tool styles through `sanitizeToolStyle` (schema); ZIP import has a total budget (`MAX_UNPACKED_BYTES` 400 MB, `MAX_ZIP_ENTRIES` 20,000, nested ZIPs included).
10. **No native `alert` / `confirm` / `prompt`.** They don't work in sandboxed hosts. Use `useUI.getState().ask(message, okLabel)`, which returns `Promise<boolean>` and renders `ConfirmDialog` in `App.tsx`. `confirmDiscard()` is async.

## Product decisions already made (keep them)

- **Continuous drawing:** a drawing tool stays active after each shape, and the new shape or arrow is selected (`afterCreate` in `Canvas.tsx`), so the Inspector shows it and typing labels it. A single `Esc` always returns to the Select tool (arrow pointer, V) and, from a drawing tool, clears the selection: mid-gesture it also cancels the gesture; in the text editor it also commits the text; it also closes the More-shapes pop-up.
- **Type to label** (`shortcuts.ts`, `labelable`; `uiStore.editSeed`): with exactly one unlocked shape, text, arrow, container or icon selected, a printable key (no ⌘/Ctrl/Alt, not Space) opens the text editor with that character replacing the label (the same as Enter + typing; `TextEditor` puts the caret after it). So one-letter tool shortcuts and ⇧ shortcuts (⇧I, ?, K) only work with no such selection; ⌘ shortcuts, Delete and arrow-key nudging are unaffected. The e2e helper `app.tool(k)` presses Esc before a tool letter for this reason. Esc pressed in an inspector input also blurs the field and returns to Select. With Select already active, Esc clears the selection.
- **Tooltips:** toolbar tools show name, shortcut and a one-line how-to (`tip` in `Toolbar.tsx`); colour swatches show a colour name plus hex (`colorLabel` in `ui/colorNames.ts`). Swatch `aria-label`s stay `<label> <hex>` because the e2e tests click by them.
- **Remembered styles per tool** (`prefs.toolStyles`, keyed `shape:<kind>`, `arrow`, `line`, `text`, …), persisted in localStorage. With a tool active, the inspector edits that tool's defaults. With objects selected, it edits those objects, **and** (pref `selectionUpdatesDefaults`, on by default) copies the new style into that tool's defaults. Existing objects never change when defaults change. There is an optional shared style across shape tools.
- **Dark theme does NOT invert the canvas.** The diagram always shows its true colours (what you see is what you export). Dark theme only restyles the app's interface. Users who want a dark canvas pick a dark canvas background.
- **Palettes** (`model/defaults.ts`): a 10-column grid of neutrals plus 10 hues, in tint, light, bold and deep strengths, plus recent colours and hex/native picker. The e2e tests click swatches by aria-label, for example `Stroke colour #1864ab`. Update the tests if you change palette values.
- **Welcome card** shows only on a fresh empty canvas. It can be dismissed (✕ / "Start with a blank canvas" / picking any drawing tool). File ▸ New diagram always gives a blank canvas with no card.
- **Swap direction** (`cmd.swapDirection`; Inspector Connector section and Arrange menu) reverses arrows in place: ends trade places, bends reverse, and curvature/label position/offset are mirrored so the route and label stay where they were. One undo step; locked arrows are skipped.
- **Round-trip highlight** (`ConnectorAnim.direction: 'roundTrip'`, `returnColor`, `turnPause`; schema v5): with the travelling highlight, one arrow shows request and response: the highlight goes out in `highlightColor`, waits at the far end for `turnPause` of the cycle, then comes back in `returnColor` (default pink `#ec4899`). Each leg moves at the one-way speed (`roundTripLeg` in `render.ts`). Arrowheads are left alone (end only by default). Other arrow animations treat it as forward; the Inspector offers it only for the travelling highlight.
- **Quick-connect** (draw.io style; `store/quickConnect.ts`, handles in `Canvas.tsx`): with the Select tool, the hovered shape and the selected shape show four arrow handles `QC_OFF` (40 screen px) outside their sides (shapes, icons and images; not text, pen, containers or locked). Resting on a handle for 350 ms opens a shape picker (`.qc-pop` in `Canvas.tsx`): copy of this shape, then `prefs.recentQuickShapes` (last 4 picked), then `QUICK_SHAPES`; a picked kind uses that tool's default style and size (`make` option), centred on the source's axis; the picker flips beside the handle when it doesn't fit. Click = `addConnectedCopy` on that side (copy keeps kind/size/style/animation, no text, no group; `nextSlot` steps sideways past anything in the way; joins the source's container) and selects it; drag = a live arrow from the source, dropped on a shape it connects, on empty canvas it drops a copy there. `cmd.quickConnect(side)` = ⌘/Ctrl+Arrow on a single selection, one undo step, pans the copy into view (`revealElement`).
- **Request ⇄ response arrow pairs** were built and parked on the branch `claude/request-response-arrows` (not merged; it also bumps the file format to v2). Pick it up from there if wanted later.
- **Icons** (icon library phases 1–3 done; next: phase 4 = optional online search, opt-in only since it needs internet). `IconElement` (`iconId`, `sketch`, `labelPos`, `frame`) is a box element: arrows attach (circle frames have a round outline), it animates like shapes, label sits below/right outside its box (`iconLabelLayout`). Vector data lives once per document in `doc.icons` and is pruned on delete; it is copied with copy/paste. Rendering: crisp `path` parts (Path2D on canvas, real `<path>` in SVG), or cached Rough.js `sets` with a matrix when `sketch` is on (one-colour icons only); `currentColor` resolves to `style.stroke`, the frame uses `style.fill`. Paints may be gradients (`IconGradient`, bounding-box or user-space, with `bbox` per part from `pathBounds.ts`); canvas draws them exactly in gradient space, SVG export writes `<linearGradient>`/`<radialGradient>` defs. `<use>` is followed only for `#id` references inside the same file. Masks, clip paths and filters are dropped (about 4% of logos look slightly different). Built-in sets (`ICON_SETS`: Tabler, Devicon, SVG Logos, Simple Icons, Kubernetes) are Iconify JSON shipped as separate files (`?url`), fetched only when a set is shown or searched; the "All" overview previews only Tabler, downloaded sets and your libraries, so opening the panel downloads one set. Search across sets uses `names.json` (regenerate with `npm run icons:index` after updating an `@iconify-json/*` package; `tests/iconSets.test.ts` fails if it drifts). Your libraries (`libraries.ts`, `useLibraries`) live in IndexedDB (`iconlib:<id>`), appear as sets `lib-<id>`, hold converted icons or raster pictures (placed as image elements), and are re-validated on load and on `.flowsketchlib` import (`sanitizeLibrary`). Manage dialog: `ui/dialogs/IconLibrariesDialog.tsx` (`hiddenIconSets` pref). SVG files dropped on the canvas become icons in that diagram only. Panel: `ui/IconsPanel.tsx`, docked left (`prefs.showIconPanel`, Shift+I), drag type `application/x-flowsketch-icon`; brand sets show a trademark note. Never ship vendor cloud icons (AWS/Azure/GCP); users import the official ZIPs instead (licence terms). ZIP import (`zipImport.ts`, `fflate` `unzipSync`): only `.svg` entries (plus ZIPs one level deep) are read; `planPack` keeps one SVG per icon (largest size, light variant), cleans AWS/Azure prefixes into names, and takes the category from the nearest non-size folder; `detectVendor` marks AWS/Azure/GCP packages, which become libraries with `vendor` set (icons get the provider's terms as their `license`, the panel and Inspector show a terms note, Azure adds Microsoft's no crop/flip/rotate note; re-importing offers to replace the old library). `.gitignore` excludes `*.zip` and `*.flowsketchlib` so provider packages are never committed. Unit tests build synthetic ZIPs; real provider packages haven't been tested here (the session can't download them).
- **Right-click menu** (`ui/ContextMenu.tsx`, reuses `ItemList` from `MenuBar.tsx`; position in `uiStore.contextMenu`): right-click selects what is under the pointer (keeping a selection it belongs to) or clears the selection on empty canvas, then shows object or canvas items. Shift+F10 / the Menu key open it at the selection (`cmd.openContextMenuAtSelection`). Inside the text editor the browser's own menu stays (spelling). Esc closes only the menu (`stopImmediatePropagation`).
- **Containers** (`ContainerElement`, `store/containers.ts`; Visio/draw.io pattern): `members` lists the elements directly inside (one container per element; nesting allowed; file validation drops missing ids, duplicates and loops). Moving a container moves `withMembers` (Canvas move, nudge, align, distribute via `moveElements`). `updateMembership` runs after moves, resizes, creation, paste, duplicate, icon placement and text growth: a shape joins the innermost container containing its centre (a container only joins one it fits entirely inside), leaves when dragged out; containers stay behind their members and grow to fit (never shrink automatically; `fitToContents` does). Arrows can be members (they move with it) but never make it grow. Deleting a container deletes its contents (Visio); `removeContainer` keeps them. Hit-testing picks a container only by its title bar (`containerHeader`) or border, so its inside behaves like canvas (selection boxes work). Containers don't rotate and don't animate by default (`anim.mode: 'off'`). Title = element text, drawn inside at the top-left; the title bar is only a hit area (no line under it). Default style: dashed, square corners. Schema v4 added containers.
- **Cmd fill cycling** (`nextFillColor` / `cycleFill` in `model/defaults.ts`, `ui/modifiers.ts`): ⌘ on a Mac (Ctrl-click is a right-click there), Ctrl elsewhere, held at mouse-down with a shape tool moves that shape's fill to the next hue in the same `HUES` row (wrapping); non-hue fills (white, greys, custom, none) start at Pale red; fill style none becomes solid. The cycled style is saved as the tool's default only when the shape is actually created (toast `Fill: <name>`). `cmd.addContainer` does the same when `cycleKeyHeld()` (global key tracker) is true.
- **Desktop app** (Tauri 2, `src-tauri/`; `persistence/native.ts`): the same web build in a native window. `isDesktopApp` (`__TAURI_INTERNALS__`) switches file I/O: `downloadBlob` (every export, library export) opens a native Save dialog and writes the file; `saveDocumentFile` saves back to the file it was opened from or last saved to (`currentPath`), Save as asks; `openDocumentFile` uses the native Open dialog. Paths chosen in the dialogs are the only ones the app may read or write (the dialog plugin adds them to the fs scope; no broad fs permissions). `tauri-plugin-persisted-scope` keeps that scope across launches, and the file each diagram belongs to is remembered (`rememberFile` / `restoreFileFor` in `persistence/files.ts`, keyed by `doc.id`: desktop = path map in localStorage `flowsketch:fileOf`, ≤50, type-checked on read; browser = the File System Access handle in IndexedDB store `flowsketch-files`, with `queryPermission`/`requestPermission` before writing), so Save writes back after a restart or opening from Recents; `cmd.loadDocument` calls `restoreFileFor`; a file picked with the `<input>` fallback or dropped has nothing to write back to (Save asks). If writing to a remembered path fails, Save asks where instead. The window has `dragDropEnabled: false` so HTML5 drag and drop (icons panel, dropped files) keeps working. Tauri packages are imported dynamically, so the browser build never loads them. The app's storage (IndexedDB, localStorage) is separate from the browser's. Unsigned personal build: not notarised.
- **Match size** (`cmd.matchSize` / pure `matchSizes`, `matchSizeItems` in `MenuBar.tsx`, shown in Arrange and the right-click menu for 2+ items): the reference is the first item in `selection` (click order; a selection box gives document order). Width/Height change only that side (pref `matchSizeKeepsProportions`, off by default, in Edit ▸ Preferences scales the other side too); Both sets w and h exactly. Targets keep their centre; only shapes, icons, images and pen drawings change (not text, connectors, containers, locked); `updateMembership` grows containers. One undo step.
- **Text to diagram + auto-layout** (`import/mermaid.ts`, `import/mermaidBuild.ts`, `layout/`; Insert ▸ Diagram from text (Mermaid), `ui/dialogs/MermaidDialog.tsx`; Arrange ▸ Auto-layout and both right-click menus): `parseMermaid` reads flowcharts (`graph`/`flowchart` + TB/TD/BT/LR/RL; shapes `[] () ([]) [()] (()) {} {{}} [//] [\\] [/\\] >]`; links `-->`, `---`, `-.->`, `==>`, `<-->`, `--o`, `--x`, labels `|x|` and `-- x -->`; chains, `&`, `subgraph … end` → containers, `direction` inside subgraphs; `%%` comments). It is relaxed (no header needed → LR; names may contain spaces) but a link needs a head or ≥3 characters, so `a -- b` stays text. Untrusted: `plainText` strips control, zero-width and bidi-override characters from the whole input; labels are plain text (`cleanLabel` strips known HTML tags only, `HTML_TAG`, so `<Token>` placeholders survive; text is never rendered as HTML); `click`/`style`/`classDef`/`class`/`linkStyle` are ignored; limits: 100k characters, 2,000-character lines, 5,000 statements, 500 nodes, 2,000 edges (`&` multiplies), 200 subgraphs, nesting depth 20 (deeper ones keep their shapes, no container); group keys are prefixed with `\u0000group:` so node names can't collide; paste detection skips text over 100k. Plain-text paste that `looksLikeMermaid` becomes a diagram (`cmd.importMermaid`, one undo step, centred, zooms out if too big). Builder (`mermaidBuild.ts`): a subgraph's `direction` applies only when none of its nodes link outside it (`ownDirection`, Mermaid's rule; otherwise it inherits); boxes are laid out in text order (`nodesIn` / first appearance), so cycles break the way the text reads; layout gaps grow to fit the arrows' labels (`connectorLabelSize`; rank gap ≤ 260, node gap ≤ 160, via `autoLayout(..., gaps)`); elbow arrows are then routed with `routeArrowsAround`. The last inserted text is kept in localStorage (`rememberMermaid` / `lastMermaid` in `persistence/storage.ts`, ≤100k characters, plain text) and prefilled in the dialog. `layered()` = cycle breaking (DFS), longest-path ranks, barycentre ordering sweeps, centred coordinates; `autoLayout(doc, dir, ids?)` lays out shapes/icons/images/containers (not text, pen, locked), arrows to items inside a container count for the container, containers inside-out (`fitToContents`), group keeps its top-left. One undo step.
- **Arrow routing** (`engine/connectors.ts`; schema v6): `straight`, `curved` (needs a non-zero `curvature` or bends; the Inspector's Curved choice sets 0.3 when there is none), `elbow` with `elbowRadius` (px, 0 = sharp; `roundCorners` turns each corner into a quadratic quarter-turn limited to half of a shared segment or a whole end segment; `control` keeps the sharp corners for handles). `ToolStyle.curvature` / `elbowRadius` carry the tool's remembered values into `makeConnector`. Default arrow routing is `straight`. **Elbow waypoints** (draw.io/Visio style): a selected elbow arrow shows a bar at the middle of each segment of `path.control` (`elbowSegments` in `Canvas.tsx`, ≥18 screen px); dragging one (gesture `segment`) sets `bends` = `moveElbowSegment(control, k, c)` (pure, `connectors.ts`): the route's corners with that segment moved to x/y = c; the first/last segment gets an `ELBOW_JOG` (20 px) next to its shape so ends stay put. `elbowRoute` passes through bends in turn, so bends that are exactly the corners reproduce the route. On release `tidyElbow` drops repeated and straight-run points. Elbow arrows show no bend circles or mid-dots; Inspector: Reset route (clears bends). Dragging an arrow's end (gesture `endpoint`) clears its `bends` live; on release (`moved`), an elbow arrow attached at both ends is re-routed with `routeArrowsAround(doc, [id], { keepAnchors: true })` (an end on a snap point stays exactly there; one undo step with the drag). Straight/curved arrows keep free waypoints (mid-dot drag adds one); double-click a waypoint removes it. Migration v5→v6 relabels curved arrows with no curve and no bends as straight (same look).
- **Route arrows around shapes** (`layout/orthoRoute.ts` pure router, `layout/routeArrows.ts`; `cmd.routeArrows`, Arrange menu and both right-click menus; also run on Mermaid import for elbow arrows): only on request, never while drawing. `routeOrtho` = A* over a sparse grid of the obstacles' edges (each shape/icon/picture grown by `ROUTE_MARGIN` 14 px; containers, text and pen aren't obstacles), straight stubs out of each end until clear, cost = length + 40 per turn + a share penalty for segments other routes already use (`markUsed`). `routeArrowsAround`: pass 1 picks the best side pair (4×4) per arrow; arrows on the same side of a shape are then spread along it (in order of their other ends; `sidePoint` keeps the point reading as that side, e.g. on diamonds); pass 2 routes from those points. Result = elbow routing + port anchors + `bends` = the route's corners, which `elbowRoute` reproduces exactly (tests check this), so the segment bars and Reset route work on them. Skips arrows not between two different unrotated boxes, locked ones and activation bars.
- **Snap points (ports)** (`PORTS` / `portPositions` / `nearestPort` in `hitTest.ts`): 12, three per side at ¼, ½, ¾ (clockwise from the top left); on shapes each is cast straight out to the outline (`rayPolygon`). `attachEndpoint` (Canvas) takes the nearest within 14 screen px; the anchor stores the normalised position. `resolveEnd` puts the `GAP` straight out of the anchor's side (`sideDir`, rotated), so quarter ports start exactly at the port. No format change (anchors were already free positions).
- **Pages** (schema v7; `store/pages.ts`, `ui/PageTabs.tsx`, page commands at the end of `commands.ts`): `doc.pages` holds every page in tab order and `doc.activePage`; the current page's elements live in `doc.elements` (its own `pages` entry is kept empty) so all editing, rendering and exports work on the current page unchanged. `allPages(doc)` fills the current one in; `serializeDocument` saves elements only inside `pages`. `parseDocument` checks each page like a whole document (ids unique across pages, arrows/containers only within their page; ≤50 pages, ≤5,000 elements per page, ≤20,000 in total); older files become "Page 1". Switching pages uses `docStore.replace` (no undo step: undo returns to the page an edit was made on); add/duplicate/delete/rename/move are undoable. Each page's view is remembered for the session (`pageViews`). Icon/picture data is pruned only when no page uses it. Tab menu = the right-click menu with `contextMenu.pageId`.
- **Sequence diagrams** (`import/mermaidSequence.ts` parser, `import/sequenceBuild.ts` builder; through `cmd.importMermaid` when the first line is `sequenceDiagram`): participants (`participant`/`actor`, `as` alias) are boxes (actors pills) with animation off; each has a **lifeline** = a dashed, unanimated line connector from its own bottom edge (anchor y = 1) to an anchor below the box (anchors may go beyond the box: x −50..50, y −50..500; `resolveEnd` puts such points exactly there, no gap). Messages are connectors attached to both participants at the same anchor height (`->>` and `-)` open arrowhead like the arrow tool, `-->>` dashed, `->`/`-->` no head, `-x` bar, `<<->>` both ends), self-messages a curved loop, `autonumber` prefixes; notes are sticky shapes; `rect rgb(…)`/`#hex` is a tinted, borderless, untitled band (`rectColor`, alpha mixed with white); `loop/alt/opt/par/critical/break/rect` (+ `else/and/option`) are transparent container frames behind, titled "kind · text / else · text". `isLifeline` / `lifelineAt` (`hitTest.ts`): arrow ends dropped on a lifeline attach to its participant at that height; dragging a lifeline's bottom end changes its length. **Activation bars** (schema v8: `ConnectorElement.bar`): a connector with both ends on one participant (anchor x = 0.5 + level·6/w), drawn by `barParts` in `render.ts` as a filled outlined bar `BAR_W` 12 px wide, not animated; `isLifeline` excludes bars. Import: `activate`/`deactivate`, `->>+` (activates the target), `-->>-` (ends the sender's), an open stack per participant (nested bars shift right), unclosed bars run to the end; message ends are then moved to the facing bar edge (`messageEnd` with `activeLevel`), self-messages to the right edge. Tools: Sequence ▸ Activation drags a bar (`addBar`: next free nesting level, placed just above its lifeline, lifeline grows); dragging a bar's end slides it along its lifeline (≥ `MIN_BAR`). Messages drawn with the tools snap to bar edges too. Not supported yet: `box` groups (participants kept), create/destroy.
- **Sequence tools** (toolbar ▸ Sequence pop-up `SEQ_TOOLS` in `Toolbar.tsx`; tool `'seq'` + `uiStore.seqKind`; pure helpers in `store/sequence.ts`, shared with the importer; gestures `seqmsg` / `seqframe` in `Canvas.tsx`): Participant/Actor = `addParticipant` (box/pill 130×50, animation off, plus `lifelineFor`; lines up with existing participants' top and lifeline length, steps right past overlaps); Message/Reply = drag from a lifeline column (`columnAt`: anywhere below a participant, even past its lifeline's end) to another, kept level at the start height, `asMessage` styling, `extendLifelines` grows both lifelines; a click with Message or the Message-to-itself tool = `addSelfMessage`; Note = the sticky-note shape tool; Frame = drag a see-through container (`makeFrame`, sent to the back with `addFrameBehind`), then its title editor opens. Styles: participant `shape:rectangle`, actor `shape:pill`, message/self `arrow`, reply `seq:reply` (dashed), activation `seq:bar` (white, thin outline), frame `seq:frame` (`seqStyleKey`; `styleKey` takes the seq kind as a third argument).
- **Message-by-message playback** (schema v9: `ConnectorAnim.window: [start, end]`, fractions of the loop): with a window the travelling highlight plays once, only inside its step (`playPhase` in `render.ts`; speed, segments and delay are ignored). The saved windows give only the ORDER (arrows sharing a window start form one step); the actual timing is `playSchedule(doc)` (`render.ts`, cached per doc): each step's share of the loop is proportional to its highlight's travel (`len + highlightLength`, ×2/(1−turnPause) for a round trip) at `PLAY_SPEED` 250 px/s plus `STEP_PAUSE` 0.35 s, so every arrow moves at the same speed; `seconds` is the loop at that speed. Direction follows the heads (`flowDirection`, `store/sequence.ts`): two heads → round trip, one head → forward (a remembered round trip is dropped) — used by `asMessage`, the sequence importer and both play-order functions; the flowchart importer gives `<-->` a round trip, so arrows light up one after another and loops stay seamless. `setPlayOrder` (`store/sequence.ts`) gives arrows windows in reading order (`inReadingOrder`: top to bottom by start point) of width 0.85/n; `clearPlayOrder` removes them; `messagesOf` = sequence messages on the page. Commands `playMessagesInOrder` / `playArrowsTogether` (Animation menu, right-click on arrows); whenever an order is set the loop length becomes `playSchedule(doc).seconds` rounded up to 0.1 s (`fitLoopToPlay`, 1–120 s; it may get shorter); imported sequence diagrams get the order automatically. The Inspector shows "Plays as step k of n". **Set play order** (`cmd.startPlayOrder` / `endPlayOrder`, `uiStore.playOrderMode`; Animation menu and the arrow right-click menu): a mode where canvas clicks only number arrows (`playOrderClick`; Shift = same step as the last; clicking a numbered arrow removes it), with numbered badges in the overlay (hollow = not in the order) and an `.order-bar` (Clear = `clearAllPlayOrder`, Done; Esc also ends it). The order lives only in the windows: `readPlaySteps` groups arrows by window start, `togglePlayStep` edits the step list, `applyPlaySteps` gives each step one window (arrows in a step share it) and removes windows from arrows not in the order (`store/sequence.ts`). Each click is one undo step + `fitLoopToPlay`. No format change.
- **Label drag** (Visio-style; `labelPlacement` / `nearestOnPath` in `engine/connectors.ts`, gesture `label` in `Canvas.tsx`): with Select, pressing inside an unlocked arrow's label box (`connectorLabelBox`, no Shift, not part of a multi-selection or group) selects that arrow and drags only its label; the arrow doesn't move. The dropped centre becomes `labelPos` (nearest point along the path) + `labelOffset` (signed distance along the normal), so it follows the arrow; within 6 screen px of the line the offset snaps to 0. One undo step; a click without movement changes nothing. **Label width** (schema v10: `ConnectorElement.labelWidth`, px 40..2000, unset = fits the text on its lines): `connectorLabelSize` in `render.ts` is the one place the label box size is worked out (renderer, `connectorLabelBox`, `TextEditor`); with a width the text wraps (`labelParts` wrap) and the height follows. A selected arrow shows the label box (dashed) and two side handles (`labelHandles`, gesture `labelWidth`, symmetric about the centre, ≥ `MIN_LABEL_W`); where an end handle overlaps a label handle `handleAt` takes the nearest. Inspector: Label width slider + Fit label to its text (unsets it).
- **Shift while moving** (`move` gesture): Shift-press on a shape adds it to the selection; on an already selected shape it starts a move with `shiftToggle`, and releasing without dragging deselects it. While dragging, Shift keeps the move horizontal or vertical.
- **Duplicate by dragging** (`move` gesture in `Canvas.tsx`): ⌘-drag on a Mac / Ctrl-drag elsewhere (`isCycleKey`, Visio/PowerPoint style) or Alt/Option-drag, checked once the drag starts, clones the moved items (`cloneElements`) and moves the copies; the originals stay. One undo step. With the modifier held, pressing on an arrow's label duplicates the arrow instead of dragging the label.
- **Default styles:** `styleOf` captures style, text style, animation and, for arrows, routing, curvature, elbowRadius and heads; `cmd.applySelectionStyleToDefaults` ("Set as default style"), `resetToolStyle` / `resetSelectionToolStyle` ("Reset default style"), `resetAllToolStyles` (asks first). The Inspector shows a reset button while a drawing tool is active.
- The grid (dots / lines / plain) is per document: View ▸ Grid, the right-click canvas menu, and the Inspector's Canvas section.
- Default arrow animation is the travelling highlight. Glow is drawn as translucent wide strokes, not blur filters, for speed.
- Live view culls off-screen elements, and the grid is a cached canvas pattern.
- Theme toggle: the top-bar sun/moon button cycles Light → Dark → System. It is also in View ▸ Theme and Edit ▸ Preferences.

## Versions and the changelog

- `CHANGELOG.md` (Keep a Changelog format) is the single source of release notes. The app shows it in Help ▸ What's new (`ui/changelog.ts` parses it; keep to `## [x.y.z] - YYYY-MM-DD`, `### Added|Changed|Fixed`, `- ` bullets, `**bold**`).
- Every user-visible change adds a line under `## [Unreleased]` at the top (create the section when it is missing; never leave it empty), written for users, not developers (developer-only changes such as tests or tooling are left out).
- A version bump (`npm version x.y.z --no-git-tag-version`) renames `[Unreleased]` to `[x.y.z] - <date>`. `tests/changelog.test.ts` fails if the `package.json` version has no dated entry.
- The About dialog reads the version from `package.json`; never hard-code it.

## Testing conventions

- Unit tests are in `tests/` (Vitest + jsdom): engine determinism and continuity, connectors, schema round-trip and sanitising, icons (`tests/icons.test.ts`: conversion, hostile SVGs, file round-trips, rendering, export, search; `tests/iconSets.test.ts`: names index in sync, gradients, `<use>`, path bounds, libraries; `tests/zipImport.test.ts`: provider package layouts, nested and plain ZIPs), containers (`tests/containers.test.ts`), history, tool styles. In jsdom, wrap byte arrays in `new Uint8Array(...)` before giving them to fflate (jsdom's TextEncoder returns cross-realm typed arrays).
- `src/main.tsx` exposes a **read-only** `window.__flowsketch` hook (`doc`, `ui`, `toolStyle`, `frame(t)`, `connectorEnds`, `pause`, `setView`, `benchRender`, `measureFps`, `history`) used by the e2e tests. Keep it working and read-only.
- Stable test selectors: `data-testid` = `stage`, `play`, `open-sample`, `start-blank`, `gif-export`, `confirm-ok`. Templates use `data-template=<id>`.
- E2E opens files with `delete window.showOpenFilePicker` so the `<input type=file>` fallback (attached to the DOM in `pickFile`) is exercised.

## Known limitations / deferred work

- 60 FPS with 100 shapes + 150 connectors was not demonstrated. It measured about 22 FPS in headless software rendering; this needs checking on real hardware. Dragging while playing a huge document is slow.
- Deferred: AI text-to-diagram (intended to plug into `store/commands.ts` as structured, validated edits — Mermaid import is the natural target format; it must never execute generated code), keyframes, easing, timeline tracks, Find, rotating multi-selections, per-word bold/italic.
- Transparent GIFs use 1-bit alpha (faint fringe on edges). Video export records in real time.
- Hachure fills regenerate when a shape is resized.
